# CPU vs GPU Data Processing --- OpenMP + CUDA

A parallel computing lab project that implements **2D floating-point
convolution** on a multicore CPU using OpenMP and on an NVIDIA GPU using
CUDA. The project compares execution time, studies CPU thread scaling,
verifies numerical correctness, and records experiment results in a CSV
file for analysis in Excel.

## Objectives

-   Implement the same 2D convolution workload using OpenMP and CUDA.
-   Compare CPU execution time, CUDA kernel time, and GPU end-to-end
    time.
-   Test different input matrix sizes and OpenMP thread counts.
-   Verify CPU and GPU outputs element by element.
-   Save benchmark results to `convolution_results.csv` for spreadsheet
    analysis.

## Workload

The program uses a 3 × 3 kernel:

``` text
 1   0  -1
 1   0  -1
 1   0  -1
```

The input is a square `float` matrix generated using a fixed random seed
(`42`) and values from the interval `[0, 1)`. The convolution uses
**valid mode** (no padding) and stride 1.

For an input matrix of size `N × N`, the output size is
`(N - 2) × (N - 2)`.

  Input matrix   Output matrix
  -------------- ---------------
  1024 × 1024    1022 × 1022
  2048 × 2048    2046 × 2046
  4096 × 4096    4094 × 4094

## Build

Run the following commands from the project directory,
`C:\CPU_GPU_Convolution`.

### 1. Compile and run the OpenMP CPU program

``` cmd
cl /O2 /openmp convolution_openmp.cpp /Fe:convolution_openmp.exe
convolution_openmp.exe
```

### 2. Compile and run the CUDA GPU program

``` cmd
nvcc -O3 -arch=sm_86 convolution_cuda.cu -o convolution_cuda.exe
convolution_cuda.exe
```

### 3. Compile the CPU/GPU benchmark

``` cmd
nvcc -O3 -arch=sm_86 -Xcompiler="/openmp" convolution_benchmark.cu -o convolution_benchmark.exe
convolution_benchmark.exe
```

### 4. Compile the parameterized experiment

``` cmd
nvcc -O3 -arch=sm_86 -Xcompiler="/openmp" convolution_experiment.cu -o convolution_experiment.exe
```

If PowerShell is used, prefix a local executable with `.\`, for example
`.\convolution_experiment.exe 4096 16`.

## Run experiments

The experiment executable accepts two arguments:

``` text
convolution_experiment.exe <matrix_size> <threads>
```

The matrix size selects the square input matrix, and `threads` selects
the requested OpenMP thread count.

Example:

``` powershell
.\convolution_experiment.exe 4096 16
```

Recommended experiment matrix:

  Matrix size   OpenMP thread counts
  ------------- ----------------------
  1024          1, 2, 4, 8, 16
  2048          1, 2, 4, 8, 16
  4096          1, 2, 4, 8, 16

### Run all 15 combinations in PowerShell

``` powershell
foreach ($size in @(1024, 2048, 4096)) {
    foreach ($threads in @(1, 2, 4, 8, 16)) {
        Write-Host "`nTesting Size=$size, Threads=$threads"
        .\convolution_experiment.exe $size $threads
    }
}
```

### Repeat each combination five times

``` powershell
foreach ($size in @(1024, 2048, 4096)) {
    foreach ($threads in @(1, 2, 4, 8, 16)) {
        foreach ($run in 1..5) {
            Write-Host "Size=$size Threads=$threads Run=$run"
            .\convolution_experiment.exe $size $threads
        }
    }
}
```

This performs 75 runs. Each successful run should append a row to the
CSV. If your source version supports a `--quiet` flag, add it to each
command to suppress the formatted report; otherwise, use the command
supported by your compiled source.

## Results and CSV logging

The experiment program is intended to append results to
`convolution_results.csv`, creating the header when the file is new or
empty. The dataset includes measurements such as:

-   Matrix size and OpenMP thread count
-   OpenMP CPU time (ms)
-   CUDA kernel time (ms)
-   CUDA end-to-end time (ms)
-   Kernel speedup and end-to-end speedup
-   Maximum and mean numerical error
-   Number of mismatches

Check the file from PowerShell:

``` powershell
Test-Path .\convolution_results.csv
Import-Csv .\convolution_results.csv | Format-Table -AutoSize
Invoke-Item .\convolution_results.csv
```

**Excel tip:** close the CSV in Excel while the experiment loop is
running, then reopen it to inspect the appended rows. Results are
appended rather than replacing earlier experiments. Back up or rename
the CSV before a fresh run if you need a clean dataset.

## How correctness is checked

The experiment compares the CPU and GPU output arrays element by
element. The documented comparison accepts an absolute difference of at
most `1e-5`.

-   **Maximum error:** largest absolute CPU/GPU difference.
-   **Mean error:** average absolute difference.
-   **Mismatches:** number of output elements outside the accepted
    tolerance.
-   **PASS:** the output comparison meets the verification criteria.

The recorded lab runs reported zero maximum error, zero mean error, and
zero mismatches. New runs should be evaluated from their own
verification output rather than assuming the same result in advance.

## Understanding the timings

-   **OpenMP CPU time** measures the CPU implementation.
-   **CUDA kernel time** measures GPU kernel execution.
-   **CUDA end-to-end time** includes the GPU computation and
    host-to-device/device-to-host data transfers, according to the
    experiment's timing implementation.
-   **Kernel speedup** compares CPU time with CUDA kernel time.
-   **End-to-end speedup** compares CPU time with complete GPU time.

A GPU kernel can be faster than the CPU computation while the full GPU
operation is slower because memory transfers and launch overhead are
included in the end-to-end measurement. Always compare the same matrix
size and report kernel and end-to-end times separately.

## Troubleshooting

### `nvcc fatal: Cannot find compiler 'cl.exe' in PATH`

Initialize the Visual Studio x64 compiler environment before compiling.
In Command Prompt, use the `vcvarsall.bat` command shown under
Prerequisites, then check `where cl`.

### `nvcc` is not recognized

Confirm that the CUDA Toolkit is installed and that its `bin` directory
is available on `PATH`. Open a new terminal after making environment
changes.

### CSV is not updated

-   Run the executable from the project directory so the CSV is written
    where expected.
-   Check that the program completed successfully.
-   Ensure the CSV is not locked by another application; close it in
    Excel while experiments run.
-   Check the file timestamp and inspect the latest rows with
    `Import-Csv`.

### Terminal output differs from this README

The exact output depends on the source version and command-line options.
Use the flags supported by your current `convolution_experiment.cu`.
Recompile after replacing the source file.

## Recorded findings

The lab dataset shows that increasing OpenMP thread count generally
reduces CPU execution time, although scaling is not perfectly linear.
CUDA kernel time and GPU end-to-end time differ because the latter
includes data movement. The recorded dataset's CPU/GPU comparisons
passed numerical verification.

Performance timings depend on hardware, drivers, system load, compiler
options, and measurement conditions. Treat the included lab measurements
as results from the recorded environment, not guaranteed values for
every machine.
